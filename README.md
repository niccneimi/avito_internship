# Кандидатогенерация для поиска услуг Авито

Отбор до 50 объявлений-кандидатов на поисковый запрос. Метрика — Recall@50
(средняя по запросам доля подходящих объявлений, попавших в топ-50).
Результат: **Recall@50 = 0.7346** на бенчмарке (чистый BM25 — 0.36).

## Идея

Поиск двухэтапный. Сначала кандидатогенерация собирает пул из трёх источников
(лексический BM25 + плотный поиск E5 + «локация × категория» по популярности),
затем CatBoost ранжирует пул и отдаёт топ-50.

## Данные и признаки — что и почему

Данные: train.parquet (пары «запрос - выбранное объявление», только позитивы),
benchmark_items.parquet (корпус, 189 тыс. объявлений), benchmark_queries.parquet (2452 запроса).

Из запроса берём: `search_query` и `search_infm_params_text` — текст для BM25/E5
(фильтры в тексте тоже помогают), `search_location_id`, `search_category`,
`search_is_delivery_search` — признаки пары. Из объявления: заголовок/описание/параметры —
текстовые индексы; локация, категория, microcat, рейтинг, отзывы, цена — числовые признаки.

Признаки пары (17 + microcat) и их смысл:
- `bm25_score`, `bm25_rank`, `in_bm25` — скор и позиция в выдаче BM25;
- `dense_score`, `dense_rank` — косинусная близость E5 и позиция;
- `in_loccat` — кандидат попал из пула «локация × категория»;
- `loc_match` — совпадение локации (сильный сигнал);
- `cat_match` — совпадение категории;
- `is_delivery`, `q_len` — контекст запроса;
- `q_in_title_frac`, `title_len` — перекрытие токенов запроса с заголовком;
- `item_rating`, `log_reviews`, `price_neg`, `log_price` — качество/популярность объявления;
- `rating_gap` — рейтинг минус минимум из фильтра «Рейтинг пользователя N звезд».

## Модели и алгоритмы

- **BM25** (bm25s) по лемматизированному тексту (pymorphy3): веса полей title×4 / desc×1 / params×2.
- **Плотный поиск** multilingual-e5-base (sentence-transformers): эмбеддинги «заголовок + описание»,
  косинусная близость;
- **Пул** = объединение BM25 top-500 ∪ E5 top-300 ∪ (локация × категория) top-200 по отзывам.
- **CatBoost YetiRank** — градиентный бустинг для ранжирования, группа = запрос.

Библиотеки: bm25s, pymorphy3, sentence-transformers,
CatBoost, pandas/numpy.

## Как проверял качество до отправки

Разметки бенчмарка нет, поэтому воспроизвёл условие бенчмарка на train: оставил пары,
чей выбранный айтем есть в корпусе (33 010 пар → 26 556 уникальных запросов) — как и
гарантировано для бенчмарк-запросов. Сгруппировал по полному набору признаков запроса,
разбил по запросам 80/20, обучил на train-части и посчитал Recall@50 на отложенных. Дополнительно следил за потолком пула (оракулом) — сколько
позитивов вообще лежит в пуле, для понимания верхней границы реранкинга.

Динамика валидация и тест: BM25 0.31 -> 0.36; +CatBoost 0.767 -> 0.699;
+E5 0.7925 -> 0.7346.

## Типы ошибок при анализе и что с ними сделали

1. **~16% позитивов в другой локации**
   Локацию нельзя делать жёстким фильтром - иначе эти случаи теряются
2. **~22% позитивов отсутствуют в BM25 top-500** (лексический поиск не ловит морфологию
   и синонимы). Добавили плотный поиск E5 в пул - потолок вырос с 0.852 до 0.878.
3. **Категория не селективна** (совпадает в ~100% и у позитивов, и у кандидатов) —
   как фильтр бесполезна; оставили признаком, модель сама назначила ей малый вес.
4. **Числовой фильтр рейтинга в тексте параметров** («Рейтинг пользователя N звезд»)
   BM25 не использует. Выделили его признаком `rating_gap`.
